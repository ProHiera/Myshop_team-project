## 상품 사진 적용 범위와 한계

`src/utils/productImages.ts`에서 제목의 구체적 품목을 우선해 사진을 고릅니다. 후디, 니트, 팬츠, 티셔츠, 원피스, 재킷, 코트, 셔츠, 데님, 백팩, 스니커즈를 구별하고 알 수 없는 제목에는 의류 행거 사진을 사용합니다. 배열 순서나 랜덤 이미지 ID로 사진을 배정하지 않습니다.

홈 상품, 상품 목록/상세/관련 상품, AI 미리보기, 찜, 장바구니, 주문, 관리자 상품/배너에 이 경로를 적용했습니다. 비어 있거나 Picsum/placehold/placeholder인 이미지 URL을 교체하고, 실제 업로드 URL은 원본 경로를 보존합니다. 주요 상품 화면에서 대표 사진에는 **품목 참고 이미지**를 표시합니다.

**현재 DB의 전 상품 사진·품목·색상·브랜드가 정확하게 일치하는지는 검증하지 못했습니다.** 저장소에는 상품 seed/덤프가 없고, `DataInitializer`는 테스트 계정만 생성합니다. 배포 설정의 기본 URL `https://pr.musecom.net` 및 상품 API에 이 환경에서 요청했을 때 HTTP 503이 반환되어 실제 상품 목록을 확인할 수 없었습니다. 새 사진은 해당 SKU의 실물 사진이라는 뜻이 아니며, 제목의 세부 색상·소재까지 맞추는 상품별 확정 매핑에는 실제 카탈로그 접근이 필요합니다. API 상품 제목을 임의로 바꾸거나 검수하지 않은 업로드 사진을 검수 완료라고 주장하지 않습니다.

상품 상세의 기존 `추천 상품 1~4`·랜덤 가격·placeholder 카드는 제거했습니다. 실제 API에서 읽은 판매 중 상품만 `함께 둘러볼 상품`에 표시하고, 목록을 읽지 못하면 이 섹션을 표시하지 않습니다.

## 실제 AI 추천 연결 수정

실제 경로는 사용자 입력 → Spring `/api/ai/proxy` → OpenAI Chat Completions → 구조화된 키워드/카테고리 → 상품 API 조회 → 제목/브랜드 점수 계산 → 실제 상품 미리보기입니다.

- 백엔드의 `{success, result: {content}}` 응답을 읽습니다. 이전 코드는 최상위 `content`를 읽어 실제 응답을 놓쳤습니다.
- 빈 내용, 사과문, 실패 envelope, 유효하지 않은 JSON을 추천 성공으로 처리하지 않습니다.
- 키워드를 실제 지원 필드 `searchField=title` / `searchTerm`으로 검색합니다. 카테고리는 `middleCategory=OUTER|TOP|BOTTOM|DRESS` 또는 `majorCategory=SHOES|ACCESSORIES|BAGS`로 변환합니다.
- 후보는 실제 API 상품만 사용합니다. 품절/재고 미상 상품은 제외하고, 키워드와 카테고리가 모두 맞지 않는 임의 첫 상품을 선택하지 않습니다.
- AI 미매칭 후 검색과 `다른 추천 보기`도 동일한 검색 URL 필드를 사용합니다. 상품 목록은 늦게 도착한 이전 검색 응답이 현재 필터 결과를 덮어쓰지 않게 보호합니다.
- 키 미설정은 HTTP 503, 공급자 요청 한도는 429, 공급자 통신/응답 실패는 502로 반환합니다. 브라우저에는 공급자 원문/키를 노출하지 않으며, 실패 이유를 성공 메시지로 덮지 않습니다.

추천 모델 응답이나 상품 API 결과를 UI에 주입하지 않았습니다. 새 데모 상품이나 가짜 추천 결과도 만들지 않았습니다.

## 확인과 실제 녹화 조건

프런트의 `npm run build`(TypeScript + Vite)가 통과했습니다. 별도 로컬 계약 확인에서 `result.content` envelope, 빈/실패 응답 거부, 실제 검색 필드 변환, 11가지 제목→품목 사진 매핑, 12개 로컬 자산 존재, 실제 업로드 URL 보존을 확인했습니다. 이 검사에 사용한 입력은 코드 검증용이며 앱/영상에 주입하지 않았습니다.

현재 환경에는 `OPENAI_API_KEY`가 없습니다. 배포 서버의 GitHub Actions secrets 값은 읽거나 노출하지 않았습니다. **실제 AI 추천 성공 영상은 접근 가능한 백엔드, 실제 상품 데이터, 이미 설정된 서버 측 API 키가 확보된 뒤에 녹화해야 합니다.** Java 21 및 MariaDB 설정(또는 명시적으로 구성한 개발 DB)이 필요합니다. 개발 Vite는 `localhost:8080`에 API를 프록시합니다.

별도 공유된 `myshop-review` 정적 서버는 production 빌드의 이미지·레이아웃 검수용입니다. API 서버나 추천 응답을 제공하지 않으며, 실제 추천 성공을 증명하는 영상의 서버로 사용하지 않습니다.

이번 범위는 메인 AI 추천입니다. 고객센터 `SupportChatWidget`의 기존 AI 응답 wrapper 문제는 수정하지 않았으며, 기존 고정 FAQ 동작과는 구분해야 합니다.
